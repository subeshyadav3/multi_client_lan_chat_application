🏛️ System Architecture Deep-Dive

Two-Tier Centralized Client–Server Architecture
All communication is strictly mediated by the server. Clients never talk peer-to-peer; this simplifies NAT/firewall traversal on local subnets and provides a single source of truth for accounts, room states, access permissions, and rate limiting.

🔒 POSIX Threads, Mutexes & Deadlock Prevention

The Four Inviolable Server Concurrency Rules
  1. Never Hold client_mutex While Broadcasting: Handlers copy client socket descriptors to a local array under lock, immediately release the lock, and then call send(). This prevents a slow or stalled client socket from locking the entire server.
  2. Snapshot Pattern (Copy-Under-Lock): Before inspecting client/room state, copy the data to stack memory. This ensures caller threads never touch deallocated memory if a client disconnects concurrently.
  3. Fine-Grained Mutex Isolation: Six independent locks (client_mutex, user_mutex, room_mutex, upload_mutex, transfer_mutex, and per-room history locks) eliminate global bottlenecking.
  4. Detached Thread Lifecycle: Server calls pthread_detach(pthread_self()) on client thread startup, ensuring kernel memory is immediately reclaimed upon disconnect without needing a join manager.

📡 Wire Protocol Specification

Design Philosophy: IRC-Style Human-Readable Text Protocol
Every frame is an ASCII line delimited by pipe characters (|) and terminated with a newline ( ). Format: TYPE|arg1|arg2|... . This enables transparent inspection with netcat, Wireshark, and tcpdump.

📦 Token-Guarded Chunked File Transfer Subsystem

End-to-End File Transfer Workflow
  1. Sender Requests Transfer: Sends FILE_REQUEST|doc.pdf|1048576|bob.
  2. Server Issues Secret Token: If an upload slot is open, server returns FILE_GRANTED|alice|doc.pdf|a8f9c2d1|1048576.
  3. Server Notifies Recipient: Bob receives FILE_OFFER|alice|doc.pdf|1048576|bob.
  4. Recipient Accepts: Bob types /accept 1, emitting FILE_ACCEPT|alice|doc.pdf.
  5. Chunk Streaming: Alice reads 2048-byte binary slices, Base64 encodes them (~2732 chars), and streams FILE_DATA|doc.pdf|a8f9c2d1|<base64>.
  6. Token Verification: Server verifies the token on every single chunk before forwarding to Bob.
  7. Assembly & Atomic Rename: Bob writes chunks into files/doc.pdf.tmp. On FILE_END, the temporary file is renamed to files/doc.pdf.
